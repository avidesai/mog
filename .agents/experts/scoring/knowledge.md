# Scoring — what I know about this repo

- Score = evidence- and reliability-weighted mean of per-metric quality terms, standardised against analytic reference moments, mapped through a quantile table (`core/data/composite_reference.json`, generated by `tools/build_reference.py`) to a percentile; 0–10 = percentile/10. Tier bands LTN <45 · MTN 45–65 · HTN 65–85 · Chadlite 85–97 · Chad ≥97. Nothing below LTN.
- Quality terms: toward_mean → −|z|; higher_better → z; lower_better → −z flat below −1 SD (adiposity never rewards gaunt). Clamp ±3.
- Weight = tier gate (A/B in) × evidence cap (strong 1 / moderate .6 / weak .1 / community .02 / contradicted 0) × reliability r = 1/(1+(noise_sd/pop_sd)²). `noise_sd` is PROVISIONAL (2%/5% CV of mean; 1°/2.5° angles) until `tools/harness.py` writes measured values.
- Band = max(cross-frame IQR, noise_sd) per metric propagated through the quality slope, ⊕ MODEL_SIGMA_STD 0.10, ±1σ, min half-width 0.15. Calibration test: a person's long-run mean lands inside a single capture's band ~68% of the time.
- Test–retest under the provisional noise table: median per-person SD ≈ 1.1 (was 1.9 before attenuation weighting). Gate: ≤ 0.6 on measured noise; the suite guards ≤ 1.2 provisional.
- Perfectly mean face scores ~10 (maximises every toward-mean term). Mathematical corner, documented.
- Metrics are treated as independent when building the reference table; correlated pairs make percentiles slightly too extreme.
- fWHR is contradicted (Geniole 2015) and carries zero weight. Community metrics are capped at 0.02.
- Most-improvable is chosen only among `modifiable` metrics (skin, adiposity, cervicomental, bigonial). Bone is never called improvable.
- Model version lives in `SCORING_MODEL_VERSION` / `ScoringConstants.modelVersion`; bump on any change that moves a score, regenerate reference + fixtures, and the app shows the "model changed" card.
- `references.json` entries marked `verify: true` have not had their figure checked against the paper.
- Three engines: Python `core/mogcore` (spec), Swift `core/swift/MogCore`, TypeScript `app/core` (`bun test app/tools`). The TS gate checks composite_std to 1e-6, percentile, the band (`score_low`/`score_high`), tier, n_scored and `model_version` against `scoring_cases.json`; `SCORING_MODEL_VERSION` in `app/core/scoring.ts` must follow a Python bump.
- A non-finite value or confidence is suppressed as `low_confidence` in all three engines, and the floor is written `not (conf >= floor)` so NaN fails it. Before 14 Nov a NaN reading scored as the best possible quality and the face came out "Chad". `tier_for_percentile` throws on a non-finite percentile.
- The denylist normalises text to NFKC in all three engines. The TS port also rewrites `\d` as `\p{Nd}` and `\b` as a Unicode boundary, because JavaScript's are ASCII-only. A differential run over every UI string and every rule's copy matched Python with 0 differences.
