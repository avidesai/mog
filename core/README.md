# mog-core

Deterministic reference implementation of Mog's three engines — **scoring**,
**recommendation**, **habit** — plus the data tables they run on. Python is the
spec; the Swift package in `swift/` is the port the iPhone app uses. Both read
the same JSON and must pass the same fixtures.

```
data/
  metrics.json             ~36 metrics: definition, reference (mean, sd) per sex with citation,
                           direction, evidence grade, provisional reliability tier, confidence floor
  references.json          every citation; `verify: true` = re-check the figure against the paper
  rules.json               30 human-authored rules with safety tiers, triggers, excludes, static copy
  denylist.json            tier-X terms; scanned at authoring time (tests) and render time (LLM output)
  composite_reference.json generated by tools/build_reference.py — quantile table for percentiles
mogcore/
  registry.py   loads + validates everything; refuses to load an inconsistent table
  scoring.py    readings → z → quality → weighted composite → percentile → 0–10 + tier + band
  planner.py    fired rules → excludes → rank → plan / professional / info + daily tasks
  habit.py      day completion, streak, one repair/month, week banking, scan windows, distress card
  denylist.py   the tier-X scanner
  cli.py        python -m mogcore.cli {score|plan|check|catalog}
tests/          the suite, including the authoring gates (run: python -m pytest -q)
fixtures/       scoring_cases.json — golden cases the Swift port must reproduce
tools/          build_reference.py, make_fixtures.py
```

## Run

```
python -m pytest -q
python -m mogcore.cli score fixtures/example_scan.json
python -m mogcore.cli plan  fixtures/example_scan.json --goals sharper_jawline better_skin --minutes 15
python -m mogcore.cli check "any generated sentence"
```

## What the score is

> A measured comparison against published population norms, weighted by
> evidence strength, expressed as a percentile of a sex-matched reference
> distribution. 0–10 is percentile ÷ 10.

Each scorable metric gets a z-score against its published norm, a signed
quality term from its direction (`toward_mean` → −|z|; `higher_better` → z;
`lower_better` → −z, flat below −1 SD so very low adiposity is never rewarded),
clamped at ±3. Weight = reliability nominal (A 1.0, B 0.6, C/D 0) × evidence cap
(strong 1.0, moderate 0.6, weak 0.1, community 0.02, contradicted 0). The
weighted mean is standardised against its analytic reference moments (so a
scan with suppressed metrics is still comparable) and mapped through a
quantile table built from the norms themselves.

Properties the tests enforce:

- faces sampled from the norms land at a **median of 5.0** and fill the tier
  bands in their published proportions (LTN <45th, MTN 45–65, HTN 65–85,
  Chadlite 85–97, Chad 97+ — nothing below LTN by design)
- bit-for-bit **deterministic**; reading order irrelevant
- fWHR (contradicted) and community metrics **cannot move** the score
- tier-C metrics display as a category and carry **zero** weight
- low confidence / occlusion / missing pose → **suppressed with a reason**, never a guess
- band = capture noise (cross-frame IQR, propagated) ⊕ a fixed model-uncertainty
  term; typical ±0.4–0.5 points; **never narrower than ±0.15**

A face at exactly the mean on every metric scores ~10. That is a mathematical
corner (it maximises every toward-mean term at once), not a real face, and the
Methodology screen should say so if asked.

## Known simplifications (v1.1 replaces them)

- Metrics are treated as independent when building the reference table.
  Correlated pairs (adiposity ↔ cervicomental) make the composite's reference
  variance slightly too small, so percentiles are slightly too extreme.
- Reliability tiers are **provisional** until the test-retest harness measures
  them. The harness output overwrites `reliability_tier` in `metrics.json`.
- Reference norms are predominantly Farkas (North American Caucasian). Where
  ancestry-specific norms exist (canthal tilt, nasal angles) they should
  replace the pooled values as the `ancestry_group` stratification lands.
- Every `verify: true` citation needs the exact figure checked against the
  paper before launch.

## Rules of the rules table

- Tier X is checked twice (before firing and before ranking) and can never render.
- Tier 3/4 never enter the ranked plan and never become tasks.
- Every daily task must come from a tier-1/2 rule; the streak counts days the
  plan is done, never scans.
- Every strong-evidence rule must cite at least one clinical reference.
- All copy is scanned against the denylist in CI. Fix the copy, not the list.

## Appearance heads — cheap path (`appearance/`)

`skin.py` and `adiposity.py` are the zero-training versions of the two appearance metrics, with tests in `tests/test_appearance.py` (clean vs blotchy, lighting-gradient invariance, tone invariance within the luma gate, geometry monotonicity). The Swift port is `ios/Mog/Geometry/Appearance.swift` and is wired into the capture pipeline. Both are proxies and say so; the week-9 harness tunes their constants against the reference ranges.
